# 技能加载机制
- 加载本技能正文：调用工具 `load_skill("coding")`
- 返回内容末尾附带的 `<available_resources>` 清单会列出本技能目录下所有可读子文件
- 按需读取子文件：调用工具 `read_skill_resource("coding", "<资源名>")`，资源名与下方表格中的文件名一致（如 `csharp-conventions.md`）

# 交互原则
编码交互原则必须准寻以下规则：
1：任何人工指令下发后都需要生成任务计划, 且根据下面 <计划生成规范> 的规则生成 (包括编码进行中, 用户也可能会提出问题或者反馈)
2：任务计划生成后需要等待用户指令进行指定的任务的开发, 且任务完成后必须打印任务列及状态, 好提供用户选择任务进行下一步操作
3：编码开始前必须遵循下面 <编码规范> 的编码约定
4：如果在交互过程中用户下达增加SKILL指令, 则严格遵循 <添加SKILL> 的约定进行

编码开始前，按涉及范围读取并严格遵循本目录下的规范文件：

| 规范 | 文件（同目录） | 何时读 |
|------|----------------|--------|
| C# 通用代码规范 | `csharp-conventions.md` | 任何 C# 编码前必读 |

规则：
- **引用 = 调用 `read_skill_resource` 工具按需读取**（skill 名固定为 `coding`，资源名与下表文件名一致，如 `csharp-conventions.md`）：需要哪份读哪份，不一次性全读。
- 两者都涉及时则遵循当前SKILL中定义的顺序, 按照从上往下的规则依次加载。约定相互冲突时, 排在后面的权重大于前面的, 意味着后面的定义覆盖前面的

# Coro 开发套件

本套件由三个项目构成：`Coro`（核心：DI / MVVM 基类 / 命令 / 日志）、`Coro.Roslyn`（源码生成器 & 分析器）、`Coro.WPF`（WPF 应用框架 / 路由 / 窗口 / 转换器）。编码前按涉及范围读取并严格遵循本目录下的套件文件：

| 套件 | 文件（同目录） | 何时读 |
|------|----------------|--------|
| Coro 核心库 | `coro-core.md` | 涉及容器、ViewModel、命令、`[Inject]`/`[ObservableProperty]`、日志、异常、扩展时必读 |
| Coro.Roslyn | `coro-roslyn.md` | 涉及源码生成产物、`partial` 要求或 `COROxxxx` 错误码时必读 |
| Coro.WPF | `coro-wpf.md` | 涉及 WPF 应用且使用了Coro开发套件时, 入口、路由、窗口、转换器、新建页面时必读 |

规则：
- **引用 = 调用 `read_skill_resource` 工具按需读取**（skill 名固定为 `coding`，资源名与下表文件名一致，如 `coro-core.md`）：需要哪份读哪份，不一次性全读
- 涉及到开发套件的代码更改, 必须咨询客户并给出文档更新清单, 由用户选择哪些更新到开发文档 (即当前目录中的Coro开发套件的.md文件)

## 计划生成规范
| 阶段 | 描述 |
|------|-----------|
| 1. 理解 | 把模糊需求变成明确目标，确认边界与验收标准 |
| 2. 探索 | 摸清现有代码：相关代码在哪、怎么组织、有哪些约束 |
| 3. 设计 | 定方案：改哪些文件、怎么改、风险点、要不要先问用户 |
| 4. 实现 | 动手写：小步推进、遵循现有风格、不夹带无关改动 |
| 5. 测试 | 验证：能编译、能过测试、覆盖核心路径与边界 |
| 6. 审查 | 收尾：对照质量自查，别留坑、别过度设计 |

## 添加SKILL
规则：
- 1：先理解用户的需求
- 2：反馈理解后的成果 (成果中不能涵盖任何有具体含义的或者跟当前项目、类等之类有关的关键字。SKILL只能是一个规范, 如果一定需要也是通用形式的, 他不能出现具体的事物)
- 3：咨询用户成果是否合理, 是否需要修改。如果合理则收入, 否则修改并重复上诉步骤
